## 2. 1단계 — 진입점 통합 (권장, 즉시 가능)

### 2.1 방식: 단일 도메인 `vapm.sampyo.co.kr` + 경로 라우팅 (확정 2026-07-21)

- 위키: `https://vapm.sampyo.co.kr/` — 현행 유지, 앱 수정 없음
- SOC: `https://vapm.sampyo.co.kr/soc/` → `127.0.0.1:8013`

| 장점 | 대가 |
|------|------|
| DNS 신청 불필요 — 기존 도메인·SSL 그대로 재사용 | SOC 앱에 `root_path=/soc` 반영 필요 (kkj8880 협의) |
| 단일 진입점 + 동일 오리진 — 향후 로그인/쿠키 공유·API 연계 용이 | SOC 템플릿의 절대경로 링크(`/static`, 리다이렉트 등) 사전 점검 필수 |

> 대안(경로 방식이 막힐 경우): 서브도메인 `soc.sampyo.co.kr` — 앱 수정이 없는 대신
> IT실 DNS A레코드 등록 필요. 와일드카드 SSL은 동일하게 재사용 가능.

### 2.2 절차

1. **nginx — 기존 vapm vhost에 location 추가** (`/etc/nginx/sites-available/vapm.sampyo.co.kr` 443 server 블록):

   ```nginx
   # SOC 영업기회 (경로 라우팅) — proxy_pass 후행 슬래시로 /soc/ 접두어 제거
   location = /soc { return 301 /soc/; }
   location /soc/ {
       proxy_pass http://127.0.0.1:8013/;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_set_header X-Forwarded-Prefix /soc;
   }
   ```

   ```bash
   sudo nginx -t && sudo systemctl reload nginx    # nginx -t 필수 (배포표준)
   ```

2. **SOC 앱 `root_path` 반영** (mortar-soc 저장소, 담당: kkj8880):
   - uvicorn 실행에 `--root-path /soc` 추가 (또는 `FastAPI(root_path="/soc")`)
     → 리다이렉트·`url_for`·API docs 경로가 `/soc` 접두어를 포함하게 됨
   - **템플릿에 하드코딩된 절대경로**(`href="/static/..."`, `location.href='/login'` 등)는
     `root_path` 로 해결되지 않음 — 전수 점검 후 상대경로 또는 `url_for` 로 교체
   - 기존 직접 접속(`10.50.20.51:8013`)도 병행 유지되므로 전환 기간 리스크 없음
3. **SOC 앱 HTTPS 전환 설정** (`soc-app/webapp.env`):
   - `SESSION_COOKIE_SECURE=false` → `true` (HTTPS 뒤에서만)
   - 카카오 개발자콘솔 **허용 도메인에 `vapm.sampyo.co.kr` 추가** (지도 JS SDK — 누락 시 지도 깨짐)
4. **상호 네비게이션 링크** — 동일 도메인이라 내부 링크처럼 동작:
   - 위키 사이드바에 "영업기회 SOC" → `/soc/` 링크 추가 (`src/components/layout/sidebar.tsx`)
   - SOC 메뉴에 "기술 위키" → `/` 링크 추가 (mortar-soc 저장소 — kkj8880 요청)

### 2.3 검증

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://vapm.sampyo.co.kr/soc/health   # 200
curl -s -o /dev/null -w '%{http_code}\n' https://vapm.sampyo.co.kr/             # 200 (위키 영향 없음)
docker inspect soc-mortar-app --format '{{.State.Health.Status}}'               # healthy
# 브라우저 확인: /soc/ 로그인 → 지도 표시 → 새로고침 시 경로 유지
```

## 3. 2단계 — 데이터 연계

SOC의 CRM(영업기회·제품맵 흡수분)과 위키의 제품 마스터(삼표 특수몰탈 15종)를 연결한다.

| 연계 | 구현 | 비고 |
|------|------|------|
| SOC 영업기회 → 위키 제품 상세 | SOC 화면에서 제품명에 `https://vapm.sampyo.co.kr/wiki/products/<id>` 딥링크 | 위키 제품 id 매핑표 1회 작성 |
| 위키 제품 → SOC 관련 영업기회 | (선택) 위키 제품 페이지에 SOC 링크 | SOC가 제품별 필터 URL 제공해야 함 |
| 제품 마스터 단일화 | 위키 PostgreSQL을 정본으로, SOC는 읽기 API 호출 | 위키 `/api/products` 이미 존재 |

- DB 직접 통합(SQLite → PostgreSQL 이관)은 3단계 판단 전까지 하지 않는다.
  SOC의 SQLite는 일일 갱신 파이프라인과 강결합되어 있어 이관 비용 > 효익.
- 인증 통합(SSO): 위키가 현재 무인증이므로 당장 불필요. 위키에 로그인 도입 시점에 재검토.

## 5. 3단계 — 완전 앱 병합 (현 시점 비권장)

| 관점 | 판단 근거 |
|------|-----------|
| 스택 | Next.js/TypeScript/Prisma/PostgreSQL vs FastAPI/Python/SQLite — 공유 코드 0 |
