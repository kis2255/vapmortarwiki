## 2. 1단계 — 진입점 통합 (권장, 즉시 가능)

### 2.1 방식 선택: 서브도메인 (경로 기반 대비 권장)

| 방식 | 예시 | 판단 |
|------|------|------|
| **서브도메인** | `soc.sampyo.co.kr` → 8013 | ✅ 권장 — nginx vhost 하나 추가로 끝, 앱 수정 없음 |
| 경로 기반 | `vapm.sampyo.co.kr/soc` → 8013 | ❌ 비권장 — FastAPI `root_path` + 정적경로 + Next.js `basePath` 수정 필요, 쿠키/리다이렉트 이슈 |

와일드카드 SSL(`*.sampyo.co.kr`)이 이미 서버에 있으므로 인증서 추가 발급 불요.

### 2.2 절차

1. **사내 DNS 등록 요청** (IT실): `soc.sampyo.co.kr` → `10.50.20.51` A레코드
2. **nginx vhost 추가** — 기존 `/etc/nginx/sites-available/vapm.sampyo.co.kr` 을 본떠 작성:

   ```nginx
   # /etc/nginx/sites-available/soc.sampyo.co.kr
   server {
       listen 80;
       server_name soc.sampyo.co.kr;
       return 301 https://$host$request_uri;
   }
   server {
       listen 443 ssl;
       server_name soc.sampyo.co.kr;
       ssl_certificate     /home/sampyopi/sam-workmanual/nginx/ssl/2026/fullchain.pem;
       ssl_certificate_key /home/sampyopi/sam-workmanual/nginx/ssl/2026/2026_sampyo.co.kr_.key.pem;
       location / {
           proxy_pass http://127.0.0.1:8013;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```

   ```bash
   sudo ln -s /etc/nginx/sites-available/soc.sampyo.co.kr /etc/nginx/sites-enabled/
   sudo nginx -t && sudo systemctl reload nginx    # nginx -t 필수 (배포표준)
   ```

3. **SOC 앱 HTTPS 전환 설정** (`soc-app/webapp.env`, 담당: kkj8880 협의):
   - `SESSION_COOKIE_SECURE=false` → `true` (HTTPS 뒤에서만)
   - 카카오 개발자콘솔 **허용 도메인에 `soc.sampyo.co.kr` 추가** (지도 JS SDK — 누락 시 지도 깨짐)
4. **상호 네비게이션 링크**:
   - 위키 사이드바에 "영업기회 SOC" 외부 링크 추가 (`src/components/layout/sidebar.tsx`)
   - SOC 메뉴에 "기술 위키" 링크 추가 (mortar-soc 저장소 — kkj8880 요청)

### 2.3 검증

curl -s -o /dev/null -w '%{http_code}\n' https://soc.sampyo.co.kr/health   # 200

## 3. 2단계 — 데이터 연계

SOC의 CRM(영업기회·제품맵 흡수분)과 위키의 제품 마스터(삼표 특수몰탈 15종)를 연결한다.

| 연계 | 구현 | 비고 |
|------|------|------|
| SOC 영업기회 → 위키 제품 상세 | SOC 화면에서 제품명에 `https://vapm.sampyo.co.kr/wiki/products/<id>` 딥링크 | 위키 제품 id 매핑표 1회 작성 |
| 위키 제품 → SOC 관련 영업기회 | (선택) 위키 제품 페이지에 SOC 링크 | SOC가 제품별 필터 URL 제공해야 함 |
| 제품 마스터 단일화 | 위키 PostgreSQL을 정본으로, SOC는 읽기 API 호출 | 위키 `/api/products` 이미 존재 |

- DB 직접 통합(SQLite → PostgreSQL 이관)은 3단계 판단 전까지 하지 않는다.
  SOC의 SQLite는 일일 갱신 파이프라인과 강결합되어 있어 이관 비용 > 효익.
- 인증 통합(SSO): 위키가 현재 무인증이므로 당장 불필요. 위키에 로그인 도입 시점에 재검토.

## 5. 3단계 — 완전 앱 병합 (현 시점 비권장)

| 관점 | 판단 근거 |
|------|-----------|
| 스택 | Next.js/TypeScript/Prisma/PostgreSQL vs FastAPI/Python/SQLite — 공유 코드 0 |
| 결합 | SOC는 데이터 수집 파이프라인(probe 10여 종 + 스케줄러)과 강결합 |
| 담당 | 저장소·담당자 분리 운영 중 — 병합 시 배포·장애 책임 경계 소실 |
| 효익 | 사용자 관점 통합은 1·2단계(도메인 + 크로스링크)로 대부분 달성 |

병합을 재검토할 트리거: ① 두 앱에 공통 로그인 요구 발생 ② 제품 마스터 이중 관리로 실데이터 불일치 발생 ③ 담당 일원화.
